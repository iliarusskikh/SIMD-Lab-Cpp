Name patterns

  • AVX: _mm256_* = 256-bit; _mm_* = 128-bit; suffix _ps = packed single (float); _epi32 = 32-bit integer lanes; _si256 = opaque integer vector.
  • NEON: v…q_… — q = 128-bit (quad); f32 / s32 = float / signed int32; vld1 / vst1 = load/store one vector.
Headers

x86: <immintrin.h> via simd_detect.hpp. ARM: <arm_neon.h>. Include the detector header; do not scatter ISA includes in every file.

02

Load / store

_mm256_loadu_ps / vld1q_f32

Load 8 (AVX) or 4 (NEON) floats from a pointer into a vector register. The u in loadu means unaligned — safe for std::vector::data(). Used in every float exercise.

01_vecadd
__m256 va = _mm256_loadu_ps(a + i);
float32x4_t va = vld1q_f32(a + i);

_mm256_storeu_ps / vst1q_f32

Store a vector back to memory (unaligned). Inverse of load. Writes step consecutive floats starting at out + i.

Aligned variants (not used in kernels; see aligned_alloc.hpp)

_mm256_load_ps / _mm256_store_ps require a 32-byte-aligned address. Faster on some x86 µarchs; undefined if misaligned. This lab sticks to loadu/storeu for simplicity.

03

Constants & broadcast

_mm256_setzero_ps / vdupq_n_f32(0)

All lanes = 0. Accumulators for dot product and reduce-sum start here (02, 07). Also used as the “false” blend input in AVX threshold flags (05).

_mm256_set1_ps(x) / vdupq_n_f32(x)

Broadcast scalar x into every lane: [x,x,x,…]. Used for α in AXPY, clip bounds, threshold, sign-bit mask (-0.0f), and init of min-accumulator to FLT_MAX.

03_fma_scale
const __m256 va = _mm256_set1_ps(alpha);
const float32x4_t va = vdupq_n_f32(alpha);
04

Arithmetic (vertical)

Vertical = lane i of the result depends only on lane i of the inputs.

_mm256_add_ps / vaddq_f32

Lane-wise a + b. Core of 01_vecadd and the accumulate step in 07_reduce_sum.

_mm256_fmadd_ps(a,b,c) / vfmaq_f32(c,a,b)

Fused multiply-add: compute a*b + c with one rounding. Watch argument order:

Computes
AVX _mm256_fmadd_ps(a,b,c)a*b + c
NEON vfmaq_f32(c,a,b)c + a*b (accumulator first)

Used in 02 (dot: acc += a*b) and 03 (AXPY: y += α*x). Needs -mfma on x86 (CMake sets this).

_mm256_min_ps / _mm256_max_ps · vminq_f32 / vmaxq_f32

Lane-wise min/max. Clip is min(hi, max(lo, x)) with no branches (04). Also used to fold candidates in array-wide min.

SSE helpers used inside AVX reductions

_mm_add_ps, _mm_min_ps — same ops on __m128 after splitting a 256-bit register in half.

05

Horizontal ops (cross-lane)

After a vertical loop you often have 8 (or 4) partial results in one register. Horizontal ops fold lanes together into a scalar.

AVX sum fold (02, 07)

IntrinsicWhat it does
_mm256_castps256_ps128(v)Reinterpret: low 128 bits as __m128 (no instruction)
_mm256_extractf128_ps(v, 1)High 128 bits → __m128
_mm_add_ps(lo, hi)Add the two halves → 4 partial sums
_mm_hadd_ps(x, x) (×2)Pairwise horizontal add; after two rounds, lane 0 holds the total
_mm_cvtss_f32(x)Extract lane 0 as a C float

AVX min fold (04)

Same split into lo/hi, then _mm_min_ps plus _mm_shuffle_ps to pairwise-min until one scalar remains, then _mm_cvtss_f32.

_MM_SHUFFLE(2,3,0,1) / (1,0,3,2) pick lane permutations so each min compares different pairs. Implemented with _mm_shuffle_ps(m, m, imm).

06

Compare, blend, abs

_mm256_cmp_ps(a, b, _CMP_GT_OQ) / vcgtq_f32(a, b)

Lane-wise “greater than.” AVX returns a float vector whose lanes are all-1-bits or all-0-bits. NEON returns uint32x4_t masks. _CMP_GT_OQ = ordered quiet compare (NaNs compare false). File: 05.

_mm256_blendv_ps(f, t, mask) / vbslq_f32(mask, t, f)

Per lane: if mask true, take t, else f. Argument order differs:

  • AVX: blendv(false_val, true_val, mask)
  • NEON: vbsl(mask, true_val, false_val)

Builds 0/1 threshold flags without an if per element.

_mm256_andnot_ps(sign, v) / vabsq_f32(v)

Absolute value. AVX clears the sign bit: andnot(sign_mask, v) with sign_mask = set1(-0.0f) (bit 0x80000000). NEON has a dedicated vabsq_f32.

07

Integer arithmetic

_mm256_add_epi32 / vaddq_s32

Lane-wise 32-bit integer add (8 lanes AVX, 4 NEON). Exact integers — no float rounding. File: 06_int32_add. Signed overflow in C++ is UB if you rely on wrap in portable code; prefer defined modular types when wrap matters.
