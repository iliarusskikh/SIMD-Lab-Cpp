Exercises 02, 03, 04, and 07 — accumulating across lanes and elements, fused multiply-add, and float non-associativity.

01

Dot product

Compute Σ a[i] * b[i]. SIMD multiplies lane-wise and accumulates into a vector of partial sums — one running total per lane — then folds those lanes into a scalar.

AVX2 accumulate (src/02_dot_product.cpp)
__m256 acc = _mm256_setzero_ps();
for (; i + 8 <= n; i += 8) {
    __m256 va = _mm256_loadu_ps(a + i);
    __m256 vb = _mm256_loadu_ps(b + i);
    acc = _mm256_fmadd_ps(va, vb, acc);  // acc += va * vb
}
float sum = hsum_avx(acc);               // fold 8 lanes → 1

NEON: vfmaq_f32(acc, va, vb) — accumulator is the first argument. Quant uses: weights·returns, correlation numerators, similarity scores (Quant Applications).

02

Horizontal reduction

After the main loop you hold 8 (AVX) or 4 (NEON) partial results. Horizontal ops fold them:

  • AVX sum: extract 128-bit halves → add → hadd twice → cvtss to scalar.
  • NEON sum: low/high halves → add → pairwise add → extract lane 0.
  • Min reduction: same split idea with min / vpmin (04).

Step-by-step intrinsic list: Catalog — Horizontal.

03

FMA — fused multiply-add

fma(a, b, c) computes a * b + c with a single rounding. Separate mul then add rounds twice. FMA is usually faster on hardware that has FMA units and slightly more accurate.

OperationAVX2NEON
FMA_mm256_fmadd_ps(a,b,c)vfmaq_f32(c,a,b)
AXPY y += αxy = fmadd(α, x, y)y = vfmaq(y, α, x)
AXPY in-place

03_fma_scale mutates y. Every timed run must restore y from y_orig or the buffer accumulates αx across iterations. Verify one clean AXPY before or after timing.

EWMA-style updates rewrite to the same FMA shape: state += alpha * (sample - state).

04

Float ordering & error

Float addition is not associative. Serial scalar sums left-to-right; SIMD sums in parallel lanes then folds. At ~10M elements the totals can differ by ~1–2% relative on this lab’s data.

  • vecadd / clip / flags: element-wise — expect near-exact match (verify_float_ranges / exact).
  • dot / sum: use verify_scalar_close with relative tolerance (~2%).
Not a logic bug by itself

SIMD ≠ bit-identical to scalar for reductions. Match within tolerance, or accumulate in double / compensated sum when financial identity matters.

05

Min / max / clip

Lane-wise min/max without branches:

clip to [lo, hi]
v = max(v, vlo);
v = min(v, vhi);

Array-wide min keeps a vector accumulator of per-lane minima, then horizontal-mins to one float. NaN behavior follows IEEE and the compare flavour; this lab uses finite test data.

06

Reduce sum (07)

Same pattern as dot product with an implicit multiply by 1: load chunks, acc += v, horizontal fold, scalar tail. Quant uses: batch means (sum/n), total PnL, exposure checks. Pair with Kahan/compensated summation when long float sums must stay tight.

07

Revision checklist

Q AVX vs NEON FMA argument order?

AVX fmadd(a,b,c) → a*b+c. NEON vfmaq(c,a,b) → c+a*b (accumulator first).

Q Why can SIMD dot ≠ scalar dot?

Float add is not associative. Parallel lane sums + fold reorder operations → small relative error at large n.

Q What must you do when timing in-place AXPY?

Reset y from the original each run, or αx accumulates across warmups/timings.

Q Clip in two ops?

max(lo, x) then min(hi, …) — lane-wise, no branches.
