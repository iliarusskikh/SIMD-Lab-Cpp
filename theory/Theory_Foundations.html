SIMD Lab C++ · Knowledge notes

Foundations { SIMD revision notes }

Core ideas behind every exercise: what SIMD is, how lanes work, why layout and bandwidth matter, and when hand intrinsics are worth it. Read this before diving into src/.

01

What is SIMD?

Single Instruction, Multiple Data: the CPU applies one operation to several values at once, packed in a wide register.

  • Happens inside one thread on one core (not “use more cores”).
  • Best fit: the same math on many independent elements (add, mul, min, compare).
  • Intrinsics (_mm256_add_ps, vaddq_f32, …) are C/C++ functions that map nearly 1:1 to those instructions.
Mental model

A SIMD register is a tiny fixed-size array in hardware (e.g. 8 floats). You load a slice of your big array into it, operate on all slots, store back, advance by the lane count, repeat.

Not SIMD: branching business logic, pointer-chasing trees, sparse maps, “do totally different work per element.” Those need different tools (threads, better algorithms, layout changes).

02

Scalar vs SIMD walkthrough

Same job: out[i] = a[i] + b[i] for i = 0 … n-1.

Scalar (1 float at a time)

scalar
for (size_t i = 0; i < n; ++i)
    out[i] = a[i] + b[i];   // one add per iteration

SIMD idea (N floats at a time)

SIMD pattern (NEON: N=4)
// one iteration processes indices i .. i+3
load  a[i..i+3] into va
load  b[i..i+3] into vb
vr = va + vb          // 4 adds in one instruction
store vr into out[i..i+3]
i += 4

Then a remainder scalar loop finishes n % N leftover elements. Full pattern: Loop patterns and 01_vecadd.cpp.

ScalarNEONAVX2
Elements / iter14 floats8 floats
Ideal arithmetic peak1×~4×~8×
Real speedup—Often less than peak when memory-bound; see below
Lab numbers vs theory

This repo’s scalar path uses SIMD_SCALAR_NO_VEC (optnone / no autovec), so it is intentionally slow. Reported speedups (often ~4–20× on NEON) compare intrinsics to that crippled scalar — useful for ranking kernels, not as “production vs -O3 scalar” claims. A normal -O3 scalar loop may already be partly vectorized and show a smaller gap.

03

Lanes, vertical, horizontal

A lane is one slot in the vector register (one float or one int32).

Vertical (most of this lab)

Lane i of the result depends only on lane i of the inputs:

vertical add
va:  [a0 a1 a2 a3]
vb:  [b0 b1 b2 b3]
vr:  [a0+b0  a1+b1  a2+b2  a3+b3]

Examples: vecadd, AXPY body, clip min/max, threshold blend. No communication between lanes.

Horizontal (reductions)

Combine lanes inside one register into fewer values (often one scalar):

horizontal sum (idea)
acc: [p0 p1 p2 p3]   // four partial sums
  →  p0+p1+p2+p3     // one float

Needed after dot product and array sum (partials live in lanes), and for array-wide min. Horizontal work runs once per reduction; the long vertical loop dominates cost. Details: Reductions & FMA.

Don’t confuse lanes with bytes

“8 floats” ≠ “8 bytes.” Eight floats × 4 bytes each = 32 bytes — that is why AVX alignment talk uses 32.

SIMD vs threads

SIMDThreads
Question answered“Same op on many elements?”“Independent tasks / cores?”
GrainLanes inside one instructionWhole functions / shards
Shared memory issuesUsually one buffer, one threadQueues, races, sync
This repoAll of itNone

They stack: thread A runs NEON on symbol 1’s arrays; thread B on symbol 2. SIMD does not replace threading; threading does not replace SIMD.

06

Memory, cache, bandwidth

SIMD lowers arithmetic cost per element. Runtime often limited by how fast you can move bytes (DRAM → cache → registers).

Arithmetic intensity (intuition)

KernelTraffic (rough)ComputeOften
vecadd2 reads + 1 write ≈ 12 B / float1 addMemory-bound
dot2 reads, 1 scalar writemul + add (FMA) per elementMore compute-friendly
threshold + blend1 read + 1 writecmp + blendCan beat branchy scalar a lot

Roofline idea: if you make the math 8× cheaper but still wait on RAM, wall time barely moves. Measure (Benchmarking) before blaming the ISA. Remember this lab’s scalar is optnone — large speedups can coexist with a memory-bound story vs a fair -O3 baseline.

Why contiguous SoA arrays matter

loadu wants a[i], a[i+1], … adjacent in memory. That matches std::vector<float> / raw arrays. Linked lists and pointer tables defeat simple SIMD.

07

Alignment (why 32 bytes)

  • std::vector<float> guarantees alignment suitable for float (usually 4 bytes), and contiguous storage.
  • It does not guarantee 32-byte alignment for AVX _mm256_load_ps (aligned load).
  • This lab uses loadu / storeu (unaligned-safe) everywhere in kernels.
  • AlignedFloatBuffer allocates 32-byte-aligned storage if you want to try aligned loads later. 32 = AVX float vector width; also divisible by NEON’s 16.

a.data() is a float* to that contiguous block — what kernels take — not a pointer to the vector object itself.

08

SoA vs AoS

AoS (array of structures) — natural for messages / ticks:

AoS
struct Tick { float price; int volume; };
Tick ticks[N];
// memory: price, volume, price, volume, ...

To SIMD on prices only you need gather or unpack. Simple loadu_ps will pull mixed fields.

SoA (structure of arrays) — natural for hot numeric loops:

SoA
float prices[N];
int   volumes[N];
// one loadu → 4 or 8 contiguous prices
Revision rule

You do not need the whole program in SoA. Keep wire/storage compact if you want; denormalize into SoA buffers for the hot path. Hand intrinsics in this lab assume that layout.

SIMD = the hardware capability. Hand intrinsics = one way to request it. All three can produce SIMD code.

This lab forces scalar with SIMD_SCALAR_NO_VEC so “Scalar vs SIMD” means true scalar vs your intrinsics — not vs an already-vectorized compiler loop.

13

Revision checklist

Q SIMD vs threads — one sentence?

SIMD: many elements, one instruction, one thread. Threads: many tasks/cores. Compose them; don’t confuse them.

Q Why isn’t speedup always equal to lane count?

Memory bandwidth, latency, remainder scalar work, and horizontal folds. Vecadd is a classic bandwidth case.

Q Why SoA for this lab’s intrinsics?

loadu needs contiguous same-type elements. AoS interleaves fields; you’d need gather or unpack first.

Q Hand intrinsics vs “using SIMD”?

Intrinsics are one way to get SIMD. Compiler autovec and BLAS also use SIMD without you writing _mm256_*.

Q Why 32 in aligned alloc?

AVX float vector is 32 bytes wide; aligned AVX loads want addresses divisible by 32. (NEON’s natural width is 16.)

✕

Skipping the remainder loop

Wrong tail or OOB when n % step != 0. Lab size 10'000'007 forces a tail.

✕

Expecting bit-identical reductions

Dot/sum reorder float adds → small relative error vs scalar is normal. Element-wise kernels should match tightly.

✕

Passing &vector into a float kernel

Kernels want float* → use v.data(), not the address of the vector object.
